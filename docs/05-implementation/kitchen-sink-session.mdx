> 一句话摘要：无关任务混在一起时，我可能误用旧前提并增加上下文成本；先保存当前目标与核验状态，再选择继续、摘要或独立会话，不能把清理会话当成文件回退。

## 现象

我常看到这样的会话：你让我修复登录接口的一个报错，修完了；接着你想起来，顺口问我「对了，帮我看看这个正则怎么写」；又过一会儿，你回来说「刚才那个登录的事，再帮我加个日志」。

一段对话里塞了三件互不相关的事。到第三件时，你会感觉我的反应明显迟钝了：开始忽略你早先定下的约定，或者把前面那个正则的上下文错误地带进了登录代码里。

## 为什么会这样

无关讨论可能占用上下文、增加处理成本，或让上一任务的假设被误用到当前任务。但不能说所有原始历史始终留在窗口里：客户端可能裁剪工具输出、压缩历史、按需检索或把工作放到独立上下文。

当前 Claude Code 官方指南仍建议无关任务之间清理会话，但也明确自动压缩和更大窗口改变了旧的容量管理习惯。任务混杂是需要观察的质量与成本风险，不是「聊三件事就必然变差」的定律。

我应保留当前目标、已核验事实和未完成事项，再选择继续、摘要或独立会话；不要为了机械清空而丢掉有效状态。

## 后果

- 我开始忽略你早先给的指令，因为它们被埋在了大量无关内容之下。
- 我可能把上一个任务的细节错误地迁移到当前任务。
- 你为了纠正这些偏差又补充更多对话，反而让窗口更拥挤——进入恶性循环。

## 最佳实践

- **任务无关时优先独立会话。** 我可以先保存原任务的进度、当前 diff、验证结果和下一步，再开新会话；相关小问题无需机械拆开。
- **继续旧任务先重建必要状态。** 读取当前文件与清单，不只依赖上段对话的印象。
- **使用 /clear 前知道它清什么。** 当前 Claude Code 中它用于清理会话上下文；它不撤销磁盘改动，也不等于删除规则 / 记忆。需要保留任务时先保存一段经过核对的交接摘要。

## 示例

**改之前（一段对话）：**

```text
你：修一下 login() 的空指针报错
我：（修复）
你：顺便，帮我写个匹配邮箱的正则
我：（给出正则）
你：好，回到 login，再帮我加上失败日志
我：（开始在 login 里东拼西凑，偶尔把邮箱正则的讨论带进来）
```

**改之后：**

```text
你：修一下 login() 的空指针报错
我：（修复）
你：/clear
你：帮我写个匹配邮箱的正则
我：（给出正则，干净利落）
你：/clear
你：给 login() 的失败分支加上结构化日志
我：（专注、准确）
```

## 版本说明

:::note 适用版本
2026-10-29 核验当前最佳实践及上下文文档。保留不相关任务分开处理的建议，去掉「全部历史永远在窗口」与全模型阈值断言。/clear 清理会话不等于撤销文件、删除持久记忆或停止所有后台工作；规则、记忆和后续检索仍可能重新载入。
:::
