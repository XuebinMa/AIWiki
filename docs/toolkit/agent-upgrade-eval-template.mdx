> 一句话摘要：你换了模型、提示词、技能或工具，不能只问我「这次看起来更好吗」。把相同任务放到固定起点，在相同预算下保留每次尝试，分别比较最终状态、越权、稳定性、成本与延迟。下面是可裁剪的工程记录模板，不是厂商的官方通过标准。

## 对照前先冻结什么

一次对照只改变你打算评估的变量。若模型、提示词和工具同时变化，就把结论写成「这个组合的变化」，不要把提升单独归因到模型。

| 固定项 | 本轮填写 |
|---|---|
| 版本与变量 | 基线 / 候选的模型标识、运行框架、提示词、技能与插件、工具 schema、代码版本；唯一变更或组合变更 |
| 输入与环境 | 任务集版本、仓库提交、租户与数据快照、时间条件、依赖与工具版本 |
| 权限与网络 | 可读写范围、禁改对象、目标地址、人工确认条件、服务端授权规则 |
| 单次预算 | token / 推理设置、工具调用和重试上限、截止时长、人工介入规则 |
| 重置与缓存 | 每次恢复的快照、跨次记忆清理、缓存策略、外部服务模拟或隔离方法 |
| 判定与重复 | 预先确定的断言、评分规则、尝试次数、失败分类与停止条件 |

不能固定的条件要记录，例如远端服务当天版本或网络波动；它们会限制归因。权限和记忆也是环境的一部分，不能只重置代码目录。

## 单个任务记录

```text
task_id / task_set_version：
用户目标与明确成功条件：
输入、环境快照与可信来源：
应有的最终状态：
禁止发生的动作、访问对象与数据外发：
遇到信息不足、权限不足或服务故障时的正确行为：
如何独立检查结果，谁维护验收断言：
如何重置副作用与持久记忆：
人工参考解或已核对的可行路径：
```

任务应包括实际失败过的情形，以及正确答案是澄清、拒绝越权或安全停止的情形。不能把「没有完成危险请求」自动计成能力下降。评测环境使用合成或经许可的数据，不用真实秘密当探针。

## 每次尝试保留什么

```text
run_id / task_id / baseline_or_candidate / trial_id：
实际版本、开始与结束时间、环境重置凭据：
最终状态证据与断言结果：
工具调用、参数、目标、权限决定与异常：
是否需要人工介入，介入内容：
实际总成本、token、工具与重试次数、用时：
结果分类：成功 / 任务失败 / 边界失败 / 评测基础设施失败
失败原因与证据位置：
```

记录足以复核的工具调用与结果；不要为了填表强求模型提供额外内部思考。轨迹可能含私有内容，要按访问权限、最小采集与保留策略保存。预算耗尽、超时与失败尝试都保留，不能仅留下最好的一次。

## 五项结果并排看

| 维度 | 基线 | 候选 | 怎样判读 |
|---|---|---|---|
| 最终状态 | 填逐任务结果与证据 | 同口径 | 真正完成了什么，是否残留重复或错误对象 |
| 越权与边界 | 填失败清单与涉及对象 | 同口径 | 若任务要求禁止外发，完成任务不能抵消外发失败 |
| 稳定性 | 填每任务每次尝试 | 同次数、同预算 | 区分偶尔成功与多次一致成功，保留失败分布 |
| 成本 | 填全部尝试的成本与计费口径 | 同口径 | 包含失败、重试、工具费用与人工介入；未知项注明 |
| 延迟 | 填逐次用时与分布 | 同口径 | 明确计时起止、排队和重试是否包含，不只给最快值 |

需要比例时，写出分子、分母与缺失项。把基础设施失败另列并说明是否重跑，不静默删掉。若报告「多次尝试至少一次成功」，同时展示每次结果；这个指标不能替代每次都可靠的要求。

## 决策记录

```text
本轮结论：升级 / 继续修复 / 保留基线
支持结论的任务与证据：
未解决的边界失败与能力回退：
可接受的成本和延迟范围，以及谁确定了这个范围：
未覆盖的任务、工具、数据与外部条件：
灰度范围、停止条件与回滚版本：
复核人和日期：
```

门槛要在看候选结果前确定。不要事后放宽断言、给候选增加预算，再把它称作相同条件下的提升。

## 适用边界

### 适合什么时候用

会反复执行的代理工作流升级，特别是模型、提示词、插件或工具定义变化可能影响外部状态时。先把真实失败收成小规模任务集，再随使用增加覆盖。

### 不适合什么时候用

只改一段静态文字、没有工具动作的一次性任务，可以直接人工核对。本模板也不能替代渗透测试、隐私证明、业务验收或高风险领域的专家判断；测试过的任务不能代表所有未来输入。

### 使用前请替换

换成实际模型版本、代码提交、数据快照、工具和费用来源；填写权限边界、每次预算、重置方式、可独立检查的断言和项目自己的通过门槛。没有快照或真实状态读取能力时，先补这层，不要拿我的自述填进「最终状态证据」。
