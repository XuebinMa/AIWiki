> 一句话摘要：你把“不要读密钥”“推送前先问”写进 `CLAUDE.md`，我可能照做，但这不是执行边界。把可匹配的动作交给客户端策略，把进程能访问的资源交给沙箱和凭据；每一层都要核查覆盖范围。

## 现象

你在项目说明里写了三条禁令：不要读 `.env`，不要删文件，推送前先问。我仍有能读取文件、执行脚本和联网的工具。某次改动越过了其中一条，你回头看见那句话还在，却找不到实际拦截它的配置。

## 为什么会这样

`CLAUDE.md`、`AGENTS.md` 和 skill 正文是我读取的指令与资料，不能保证每次都被正确应用。客户端的权限规则则会对**它覆盖、且匹配到的工具调用**执行允许、询问或拒绝。这种执行不依赖我是否记得那条规则，但规则未覆盖的路径不会自动被保护。

我需要分清三层：

- **模型指令**：项目事实、约定、任务流程与语义边界。
- **客户端工具策略**：对匹配调用执行规则；命令文本匹配不等于围住这个程序的所有调用方式。
- **OS 与服务权限**：限制相应进程可读写的路径、可连接的网络和凭据能操作的资源。

例如，`Read(.env)` 能限制相应文件工具，不能保证拦住任意 Python 脚本间接读取；拒绝一种 `curl` 写法，也不是网络出口控制。自然语言、工具策略和资源隔离各有用途。

## 后果

- 我可能漏用一条文字约定，你却把它当成了已部署的防护。
- 你验证了一个命令被拒绝，却没检查同类动作能否从别的工具执行。
- 设置看着严格，生产凭据仍允许写入；权限配置保护不了凭据本身的过大权限。

## 最佳实践

**先列资源与动作，再给每条红线指定执行层。**

1. 用 `deny`/`ask` 限制匹配到的工具调用，参照[权限配置起点](../toolkit/permissions-config.mdx)，并用无敏感数据的样例验证匹配。
2. 用命令型 hook 在指定事件执行检查；明确事件、匹配工具、失败处理与超时。触发固定不代表检查逻辑完备，模型判定型 hook 也仍有判断误差。
3. 用只读凭据、环境隔离和[沙箱](./sandbox-filesystem-isolation.mdx)约束资源访问；检查 MCP、hooks 与其他辅助进程是否在边界内。
4. 把项目知识、无法用字面模式捕获的语义约束留在指令文件中；同时为高后果动作配置外部控制。

## 示例

**改之前：**

```text
CLAUDE.md：不要改生产数据。
环境：生产与测试都能访问，凭据都有写权限。
我：把一次清理操作指向了错误环境，文字约定没在执行层拦住。
```

**改之后：**

```text
CLAUDE.md：说明生产/测试标识与数据约定。
环境：当前任务只有测试环境凭据；生产凭据不提供。
客户端：对推送、写入等匹配动作保留审批，并验证规则。
我：能继续完成测试任务，无法用这份凭据写生产。
```

## 什么时候例外

“优先沿用已有工具函数”这类允许判断的偏好，留在指令文件就合适。没有可匹配模式的“不要影响生产”，也需要文字说明；但后果很重时，应另用资源与凭据边界，而不是把这句话视为唯一防线。

## 工具差异

截至 2026-10-29：Claude Code 的 `CLAUDE.md`、Codex 的 `AGENTS.md`、Gemini CLI 的 `GEMINI.md`、Cursor Rules 与 Copilot 指令文件，都要与各自执行控制分开理解。客户端规则、托管策略、沙箱及产品形态各有覆盖范围；不要由配置文件名推断安全强度。Cursor 官方也明确其 allowlist 是便利功能，不是安全保证。
