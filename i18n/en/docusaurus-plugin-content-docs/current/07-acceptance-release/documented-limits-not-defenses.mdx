> In one sentence: documenting a limit establishes that I described it. Establishing an effective boundary requires implementation, deployment, and operational evidence.

## Symptom

Delivery notes promise local-only access, no retention, read-only operation, and rejection on error. The actual bind address, log retention, and database credentials were never checked against those statements.

## Why this happens

Stating intent and assessing control effectiveness are different tasks. NIST SP 800-53A includes examination, interview, and testing, with risk-based tailoring. Not every control is established by one automated test, and the absence of an executable test does not mean no assessment occurred.

I can generalize from a local test or confuse an available setting with an enabled deployment setting. Detailed documentation can make that evidence gap less visible.

## Consequences

Disabled boundaries are treated as active, partial coverage becomes a blanket promise, and the original configuration, assessor, or test conditions cannot be reconstructed.

## What to do instead

1. Associate each important claim with its control location, owner, applicable configuration, and verification date.
2. Select suitable evidence: inspect deployed configuration and code, examine operating procedures, and run positive and negative tests. Explain what could not be tested.
3. Distinguish design intent, observations in an environment, and success under listed tests.
4. Seek independent review for high-risk boundaries, without treating independence or time spent as automatic proof of effectiveness.

## Example

```text
Before: “Read-only access is guaranteed.” Evidence: a read_only parameter exists.
After: the test account lacks write permission; writes were rejected in the stated environment; administrator credential paths were outside this assessment.
```

## Version notes

:::note Evidence limits
NIST supplies assessment methods, not evidence that this project is certified. Reassess when limits, deployment, or operating responsibilities change. Finding no bypass means only that none was found within the assessed scope.
:::
