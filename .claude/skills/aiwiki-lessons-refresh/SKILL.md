# AiWiki 项目经验刷新

将真实项目中的失败经验转化为可核查、可迁移的百科内容。与 `aiwiki-research-refresh` 共用写作和证据标准；内部经历是候选线索，不自动成为可公开证据。没有合格候选时报告无新增。

## 范围与本地状态

- 只读维护者明确授权的源目录；项目名称被提及不等于授权扫描其全部记忆。先确认现有任务中的授权范围，只在范围确实缺失时询问。
- 源项目、目录、上次扫描位置和排除理由存于本仓库忽略的 `.claude/lessons-harvest-state.md`，不在公开 skill 中硬编码个人路径或其他项目细节。
- 状态仅写入本仓库，不修改源项目的记忆或配置。读写能否执行依本次工具、沙箱和授权判断，不沿用某次历史环境的结论。
- 内部材料用于分析；发布前概括、脱敏并核对授权。凭据、个人数据、私有路径、未公开研究和客户信息不进入公开候选表、issue、PR 或正文。

## 先读

- `CLAUDE.md`、`STYLE-GUIDE.md`、`terminology.md`、`CONTRIBUTING.md`：当前写作、证据、术语和交付约定。
- `.claude/skills/aiwiki-entry-author/SKILL.md` 与 `.claude/skills/aiwiki-translator/SKILL.md`：条目和双语流水线。
- 本地扫描状态及 `BACKLOG.md`：避免反复评估已处理候选。

## 流程

### 1. 建立去重和扫描范围

用 `rg --files docs` 和 `BACKLOG.md` 确认现有主题、slug 及待办。按本地状态读取已授权范围内尚未扫描的材料；首次运行也不自动扩展到其他项目。AiWiki 自身的经验沿用 `BACKLOG.md` 的取材约定。

### 2. 筛选可迁移的失效模式

候选须满足：

- 是 AI 编码 agent 的通用失败模式，能对应 `docs/mechanisms.mdx` 的根因分类。
- 能说明与现有条目或补例的区别；相同机制优先补例，不为凑数拆新条目。
- 有独立于内部经历的可核查外部佐证，才考虑独立成条。优先厂商文档、漏洞公告、事故当事人复盘及原始研究，实际打开核对标题、版本、条件和结论。

特定仓库的操作参数或环境知识留在本地状态。缺少外部佐证的经历最多作为待确认补例线索，不能写成普遍事实或公开未获许可的内部细节。

### 3. 形成候选与授权结论

候选表记录新条目或补例、脱敏后的失效机制、拟归属文章、已核查的外部来源和去重理由。内部来源追踪留在忽略的本地状态；当前会话仅展示用户需要判断的最少信息。

未获具体内容授权时，先保留本地候选供用户审阅。已有明确授权则按其范围继续；不要重复索取同一授权。无人值守也不自动公开候选，不因允许研究就推定允许创建 issue、PR、合并或部署。外部写入遵循当前会话的授权。

### 4. 写作与双语同步

经授权的新条目沿用 entry-author 和 translator；补例同步修改现有中英段落。按需更新术语、分类翻译、机制索引、sidebar_position、计数与拼写词典。内链使用仓库现有相对链接约定。未采纳但值得后续处理的公共选题写入 `BACKLOG.md`，私有来源细节仍留本地。

### 5. 验证与交付

执行 `CLAUDE.md` 的完整质量闸门，包含 AutoCorrect、Vale、cspell、i18n、镜像及深层镜像、计数、内容/MCP 检查与双语构建。缺少工具时先解决依赖或如实记录阻断，不把简化搜索当作同等检查通过。

按实际结果更新本地扫描状态，记录覆盖位置、入选或排除理由、已落库条目。生成检查无误不等于已公开；状态区分候选、已写作和已发布。

提交前核对真实 diff 和暂存文件，确保扫描状态、巡检报告和私有材料未被跟踪。同步远程主线，按仓库约定集成更新，不强推；只执行当前用户已授权的公开交付步骤。
